# Модуль 00 — SSR с нуля

> **Для кого:** вы знаете React/Vite SPA, но SSR — «чёрный ящик». Этот урок объясняет всё до первой строки Nuxt-кода.

## Что такое «рендеринг»?

**Рендеринг** — превращение данных и компонентов в HTML, который видит пользователь.

В вашем `vue-3-course` (и типичном React-приложении) используется **CSR — Client-Side Rendering**.

## CSR (то, что вы уже знаете)

```
Браузер запрашивает index.html
    ↓
Получает: <div id="app"></div> + script.js (пустая оболочка)
    ↓
Скачивает и выполняет JavaScript
    ↓
Vue/React монтируется, делает fetch API
    ↓
Появляется контент на экране
```

**React-аналог:** `createRoot(document.getElementById('root')).render(<App />)` — всё происходит в браузере.

**Минусы CSR для публичных сайтов:**
- Google/соцсети видят пустую страницу (боты не всегда ждут JS)
- Пользователь видит белый экран, пока грузится JS
- Медленный First Contentful Paint на слабых устройствах

## SSR — Server-Side Rendering

```
Браузер запрашивает /blog/my-post
    ↓
Сервер (Nuxt/Nitro) получает запрос
    ↓
Сервер загружает данные (API/БД)
    ↓
Сервер запускает Vue и рендерит компоненты в HTML-строку
    ↓
Браузер получает готовый HTML с текстом статьи
    ↓
Скачивает JS → hydration (оживление)
    ↓
Дальнейшие клики — как SPA (без полной перезагрузки)
```

**React-аналог:** `renderToString(<App />)` на сервере — тот же принцип, Nuxt делает это автоматически.

## SSG — Static Site Generation

HTML собирается **один раз при `npm run build`**, кладётся на CDN.

- Блог, документация, лендинги — идеально
- Данные меняются редко

Nuxt: `routeRules: { '/': { prerender: true } }`

## Hydration (гидратация) — важно понять

Сервер прислал HTML:
```html
<button>Click me</button>
```

Браузер показывает кнопку сразу. Потом загружается JS, Vue «подключается» к уже существующему DOM и вешает обработчики (`@click`).

**Если HTML с сервера ≠ то, что Vue нарисовал бы на клиенте** → ошибка hydration mismatch.

Поэтому нельзя в SSR-компоненте писать `Math.random()` или `new Date()` в шаблоне без осторожности — сервер и клиент дадут разные значения.

## Сравнительная таблица

| Режим | Кто рисует первый HTML | Когда данные грузятся | SEO | Пример |
|-------|------------------------|----------------------|-----|--------|
| CSR | Браузер (после JS) | `onMounted` / `useEffect` | Слабо | Admin dashboard |
| SSR | Сервер при каждом запросе | На сервере до HTML | Отлично | Новостной сайт |
| SSG | Build-time | При сборке | Отлично | Документация |
| SPA island | Браузер | Клиент | Не нужен | `/admin` в Nuxt |

## Когда SSR нужен вам на работе

**Нужен:**
- Публичные страницы (блог, каталог, лендинг)
- Open Graph превью в Telegram/Slack
- Быстрый первый экран на мобильном

**Не нужен:**
- Закрытый admin после логина
- Внутренние инструменты только для сотрудников
- Тяжёлые виджеты с `window` / WebGL

В Nuxt можно смешивать: `/blog/**` — SSR, `/admin/**` — `ssr: false`.

## Упражнение

1. Запустите `vue-3-course`: `npm run dev`
2. Откройте `http://localhost:5173` → **View Page Source** (Ctrl+U)

4. После прохождения модуля 03 повторите на `nuxt-lab` `/blog` — увидите заголовки постов в исходном HTML

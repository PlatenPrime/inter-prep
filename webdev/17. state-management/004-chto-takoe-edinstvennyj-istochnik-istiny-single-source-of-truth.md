# Q004. Что такое «единственный источник истины» (Single Source of Truth)?

> **Источник:** [17. state-management.md](../17.%20state-management.md) · **Тема:** State Management

---

## Короткий ответ

**Single Source of Truth (SSOT)** — принцип, при котором любые данные хранятся в одном каноническом месте, а все остальные части системы только *читают* их оттуда. В Redux это означает, что всё состояние приложения находится в одном объекте-дереве внутри единственного Store. Любое расхождение между «копиями» данных в разных местах устраняется по определению — копий нет.

---

## Развёрнутый ответ

### Суть и определение

SSOT — общий архитектурный принцип, не специфичный для Redux. Его суть: данные не дублируются. Каждая сущность имеет **одно** авторитетное хранилище, а остальные получают данные через чтение (запрос, подписку, вычисление).

В контексте Redux SSOT означает:
- Один Store (`configureStore` создаёт ровно один экземпляр)
- Один объект-дерево состояния (`store.getState()` возвращает полный snapshot)
- Компоненты не хранят копий данных из store — только вычисленные/отфильтрованные представления через `useSelector`

### Как это работает

Без SSOT (типичные проблемы до Redux):
```
Компонент A — держит user.name в this.state
Компонент B — держит user.name в localStorage cache
Компонент C — получил user.name через props час назад
→ Три источника, могут рассинхронизироваться
```

С SSOT (Redux):
```
Store { user: { name: 'Alice', role: 'admin' } }
    ↓           ↓           ↓
Компонент A  Компонент B  Компонент C
(useSelector) (useSelector) (useSelector)
→ Все читают одно и то же, всегда актуально
```

При изменении (`dispatch(updateUser({ name: 'Bob' }))`):
- Store обновляется один раз
- Все компоненты, подписанные через `useSelector`, получают новое значение автоматически
- Нет ручной синхронизации между источниками

### Практика и применение

**Где SSOT критичен:**
- **Авторизация** — `auth.user` в store; компоненты, navbar, middleware — все читают один объект
- **Корзина** — товары синхронны между страницей каталога, мини-корзиной и чекаутом
- **Настройки** — тема, локаль; любой компонент читает из одного места без риска расхождения

**Нормализация как продолжение SSOT:**
Если хранить сущности в нескольких форматах (массив + словарь по id), это нарушает SSOT. Правило: сущности хранятся **один раз** в нормализованной структуре `{ ids: [], entities: {} }`, а агрегаты вычисляются через селекторы:

```typescript
// Нарушение SSOT — данные продублированы
state = {
  users: [{ id: 1, name: 'Alice' }],         // массив
  selectedUser: { id: 1, name: 'Alice' },    // копия! может устареть
}

// Корректно — selectedUserId как ссылка, данные в одном месте
state = {
  users: { ids: [1], entities: { 1: { id: 1, name: 'Alice' } } },
  selectedUserId: 1,    // только ключ
}
// Актуальные данные вычисляются: selectUserById(state, 1)
```

### Важные нюансы и краеугольные камни

- **SSOT не означает «всё в Redux»** — серверный кеш (TanStack Query), форма (React Hook Form), UI-состояние модалки — имеют свои локальные «источники истины»; SSOT применяется внутри каждого уровня
- **SSOT + кеш** — если данные дублируются между Redux store и HTTP-кешем, возникает новая проблема рассинхронизации; решение: либо только один из них, либо явная инвалидация
- **Иммутабельность усиливает SSOT** — когда state неизменяем, чтение гарантированно не меняет источник и не создаёт «скрытых» копий через мутации
- **Производительность** — единый большой объект потенциально вызывает перерисовки; мемоизированные селекторы (`createSelector`) позволяют компонентам подписываться только на нужную часть

### Примеры

```typescript
// Правильная структура store: нормализованные данные, никаких дублей
interface AppState {
  products: {
    ids: string[];
    entities: Record<string, Product>;
  };
  cart: {
    itemIds: string[];          // ссылки на products, не копии
    quantities: Record<string, number>;
  };
  ui: {
    selectedProductId: string | null;  // ссылка, не копия продукта
  };
}

// Вычисляемые данные — через селекторы, не дублирование
const selectCartProducts = createSelector(
  (state: RootState) => state.cart.itemIds,
  (state: RootState) => state.cart.quantities,
  (state: RootState) => state.products.entities,
  (itemIds, quantities, entities) =>
    itemIds.map(id => ({
      ...entities[id],
      quantity: quantities[id],
    }))
);
```

```typescript
// Пример нарушения SSOT и последствия
// ❌ Антипаттерн: компонент хранит локальную копию данных из store
function UserProfile() {
  const user = useSelector(selectUser);
  const [localUser, setLocalUser] = useState(user); // локальная копия!

  // При изменении store — localUser устаревает
  // При изменении localUser — store не знает об изменении
  // Два источника истины = баги
}

// ✓ Правильно: состояние только в store
function UserProfile() {
  const user = useSelector(selectUser);        // читаем
  const dispatch = useDispatch();

  const handleNameChange = (name: string) => {
    dispatch(updateUser({ name }));            // пишем через store
  };
  // Компонент не хранит копию — только отображает
}
```

## На что обратить внимание на собеседовании

### Каверзные follow-up (что спросят дальше)

- **Должно ли всё состояние быть в Redux?** — Нет; серверный кеш, локальный UI-стейт (открыта ли модалка), состояние формы — могут иметь свои источники истины; SSOT применяется на каждом уровне.
- **Что такое нормализация состояния и зачем?** — Хранение сущностей без дублирования в плоской структуре; предотвращает рассинхронизацию при обновлении одной сущности в нескольких местах.
- **Как SSOT связан с иммутабельностью?** — Иммутабельность гарантирует, что чтение состояния не создаёт «скрытых» копий через мутации; вместе они делают SSOT надёжным.
- **Может ли нарушить SSOT использование `useState` рядом с Redux?** — Да, если `useState` хранит копию данных из store; решение — хранить в `useState` только производные от store или независимые данные.

### Красные флаги (чего не говорить)

- «SSOT означает что вообще нельзя использовать useState» — нет, локальное UI-состояние (hover, focus, форма) вполне может жить в `useState`.
- «В Redux несколько источников истины — по одному на каждый slice» — slice это часть одного store; источник истины один, просто разбит на домены.
- «SSOT это паттерн только для Redux» — SSOT общий архитектурный принцип; применяется в базах данных, системах конфигурации, API.
